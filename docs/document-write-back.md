# 文書で直した値を台帳へ書き戻す（決定のとき）

対象: `apps/legalbridge-v3`（`server/documents/write-back.ts`、`issue-service.ts` の決定）

文書（発注書・検収書・役務提供完了通知書・計算書・条件書・契約書）で、条件明細・取引先から出た値を直して決定したら、
その値を台帳にも反映する。下書きの保存では反映しない（試しに直しただけの値を入れない）。決定と同じ取引の中で行い、
決定の結果（画面の「決定しました」）と監査記録（`document.write_back` と各台帳の記録）に何を変えたかを残す。

## 1. 支払日

| 文書 | 直す欄 | 反映先 |
|---|---|---|
| 発注書（国内・海外） | 明細の行の支払日 | その行の予定の回（`condition_schedules.pay_on`）。行は回（`schedule_id`）を持つ。回を持たない古い下書きの行は、条件の回が 1 つならその回 |
| 検収書 | 明細の行の支払日 | その行の実績の回。回の無い実績は支払の予定日だけ |
| 検収書・役務提供完了通知書・計算書 | 頭書きの支払日（`PAYMENT_DATE`・`paymentDueDate`・`支払期日`・`sc_payment_date`） | 行で直していない実績の回 |

- 「直した」は、条件から組み直した既定の値と違うこと。検収書の行の支払日は納品日からの既定で出るので、既定のままなら予定の支払日と違っても反映しない。
- 何回分かを 1 行にまとめた行（期間の支払日）は回を 1 つに決められないので反映しない。
- **支払も動かす。** 反映した回の実績（または行の実績）に割り当てた支払の予定日（`payments.due_on`）を同じ日にする。支払済みの支払は動かさず、結果に「支払済みのため動かしていない」と出す。
- 検収書から支払を立てるとき、予定日は検収書の行に刷った支払日（人が直していればその日）を先に使う（以前は納品日からの既定だけで、直した日が支払に届いていなかった）。

## 2. 相手方の通知先

文書の相手方の担当者の欄（`NOTICE_CONTACT_*`・`通知先担当者/電話/メール`・`VENDOR_CONTACT_*`、IN の条件書の `Licensor_担当者/電話/メール`・`licensorContact`）を、
取引先（受取人 → 載せた条件の相手先 → 合意の相手先）の **主担当** にする。

- 同じ人（氏名。無ければメール。空白・大文字小文字は見ない）がいれば、入っている値で違うところを直す。いなければ主担当として足す。
- 主担当の印はその人に移し、ほかの人からは外す（その人のほかの印＝署名者・請求先は残す）。
- 主担当がすでに同じ値なら何もしない。OUT の文書の許諾者の欄は当社なので読まない。

## 3. 金額・納期・業務期間（発注書の明細の行）

| 行 | 直す欄 | 反映先 |
|---|---|---|
| 予定の回の行 | 金額／納品日／業務期間 | その回の予定額（`planned_amount`）／納期（`due_on`）／役務提供期間（`service_from`・`service_to`） |
| 回の無い条件の行 | 金額・単価・数量／納品日／業務期間 | 条件の定額・単価・数量／納期（`delivery_due`）／期間（`term_start`・`term_end`） |

- 既定（条件から組んだ行）と違うものだけ。まとめた行・条件に回があるのに回を持たない行は反映しない。
- 金額は円の条件だけ（外貨は紙の額と台帳の最小単位がずれる）。
- 反映しないもの（結果に理由を出す）：実績の付いた回の予定額／実績・支払のある条件の金額（条件明細で改訂する）／許諾の条件の期間（許諾期間は契約の中身）／条件の決まりに合わない値（終了が開始より前など。1 つずつ試し、合わなければその値だけ戻して決定は止めない）。
- 検収書の行の金額は実績の額（検収の「予定と違う額」で扱う）なので反映しない。
