予算統合のための構想図 ・ 2026年11月

四つのプロジェクトを、
四つの台帳で一つにする

取引先管理、情報資産管理、個人情報保護運用、契約書管理の四つは、同じ「取引先」と「契約」のデータを別々に扱おうとしています。土台の台帳を一つにして、四つを柱として載せれば、重複する費用をまとめて一本の予算にできます。CloudSign と奉行シリーズは動かさず、統合する側が合わせます。

フェーズごとの循環

フェーズごとに、循環の中心へ台帳を一つ作る

各フェーズでは、業務が一周する流れを決め、その中心に新しい台帳を一つ作ります。業務は台帳を読み書きしながら回り、次のフェーズの台帳は前の台帳に取引先 ID でつながります。

四つの台帳がつながった姿

四つの台帳は取引先台帳を軸につながり、最後に一つの統合台帳として使えるようになります。

実線は取引先 ID でのつながり、点線は契約 ID でのつながりです。どの台帳も既存のテーブルの構造は変えず、横に足す形で作ります。

全体の絵

統合計画の構造（台帳がそろった後）

そのプロジェクトが主に持つ機能 ほかのプロジェクトと共有して使う プロジェクトをまたぐ確認 動かせないシステム（入れ替えない）

点線の箱は導入候補のサービスで、まだ決まっていません。鍵の印の二つは入れ替えず、台帳からつなぐだけにします。奉行シリーズからは支払・入金の実績を受け取り、与信管理に使います。

つなぎ目

プロジェクトが重なる五つの場所

別々に予算を取ると、ここで同じものを二度作ることになります。統合する理由はこの五つです。

取引先情報資産個人情報契約

取引先は一つの台帳に

委託先台帳、取引先マスタ、契約の相手方を法人番号で一つにまとめます。

別々だと：三つの台帳に同じ会社を登録し、名前の揺れで突き合わせができない

取引先契約

締結前の確認を一回で

反社チェックと与信の限度を、契約を CloudSign で送る直前にまとめて確かめます。

別々だと：部署ごとに反社チェックを頼み、結果が契約の記録に残らない

情報資産契約

契約で受け渡す情報を資産に

NDA や委託契約で受け取る・渡す情報を、締結と同時に情報資産台帳へ載せます。

別々だと：契約は結んだが、その情報がどこに保管されているか誰も知らない

個人情報取引先契約

個人情報の委託は三点セット

委託先の評価、委託契約（再委託・事故報告の条項）、預ける個人情報の台帳を一つの記録でつなぎます。

別々だと：委託先の評価と契約条項が食い違っても気づけない

取引先契約

お金の実績を与信に戻す

奉行シリーズの支払・入金の実績を取引先ごとに受け取り、与信の見直しに使います。

別々だと：経理と法務が同じ取引先の状況を別々に調べる

動かせないもの

CloudSign と奉行シリーズには合わせる

二つとも入れ替えません。予算に入るのは「つなぐ費用」だけで、乗り換えの費用は入れません。

CloudSign（電子契約）

役割
署名と締結の記録。契約締結管理の出口
つなぎ方
LegalBridge から署名依頼を送り、締結完了の通知を受けて契約の記録を更新
今の状態
署名依頼の送信で宛先が拒否されるエラーの切り分け中（docs/cloudsign-delivery-troubleshooting-fix-plan.md）
注意
API から送ると CloudSign 側の承認機能が働かないとする解説がある。社内の承認は LegalBridge 側で確かめる

奉行シリーズ（会計）

役割
仕訳・支払・入金の正本
つなぎ方
まず CSV（汎用データ受入）で取引先と仕訳を渡し、API の契約後に直接送る。支払・入金の実績は与信管理へ受け取る
今の状態
連携なし。経理提出用エクセルを手で渡している
注意
API の利用には「API バージョン」の契約が要るとする事例がある。使っている製品と版の確認が先
予算の束ね方

費目を四つのプロジェクトから集め直す

金額は見積もりを取ってから入れます。ここでは、どの費目を一本にまとめられるかだけを示します。

費目中身別々なら出していたプロジェクト統合後
共通の台帳LegalBridge の取引先・人物・情報資産・判断の履歴の拡張四つすべて（それぞれ台帳を用意）一本にまとめる
反社チェックSansan のオプションなどの利用料・照合件数取引先管理、個人情報保護（委託先）取引先管理に寄せる
与信データ信用調査データの利用料取引先管理取引先管理
情報資産・委託先の管理SecureNavi などの利用料情報資産管理、個人情報保護一つの契約を両方で使う
CloudSign との連携署名依頼の送信と締結通知の受け取り契約書管理契約書管理（CloudSign の利用料は今のまま）
奉行との連携CSV の出力、その後 API。実績の受け取り取引先管理（与信）、経理一本にまとめる（奉行の利用料は今のまま）
移行・データ整備既存の取引先・契約・資産の名寄せと登録四つすべて一回で済ませる
進め方

土台から順に建てる

STEP 0 ・ 予算と決め事

統合の合意

  • 四つのプロジェクトの予算を一本の計画にまとめる
  • 台帳の正本と、見られる人を決める
  • 候補サービスの見積もりを取る
STEP 1 ・ 土台

取引先を一つに

  • 取引先・委託先・相手方を法人番号で名寄せ
  • 反社チェックの結果を取り込む
  • CloudSign の送信エラーを解消する
STEP 2 ・ 締結

締結前の確認

  • 反社・与信の確認がそろってから CloudSign へ送る
  • 締結完了で契約の記録を更新
STEP 3 ・ 情報

情報資産と個人情報

  • 情報資産台帳を整え、個人情報を含むものに印
  • 委託契約と委託先評価をつなぐ
STEP 4 ・ お金

奉行と与信

  • CSV で奉行へ取引先と仕訳を渡す
  • 支払・入金の実績で与信を見直す

機能の調査の詳細は「名刺から契約満了まで」の構想図にまとめています。
