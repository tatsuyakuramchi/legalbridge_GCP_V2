# 共著の取り分（出版の利用許諾計算）

対象: `apps/legalbridge-v3`（A-068）。許諾料の台帳（docs/royalty-ledger.md）の続き。

## 1. 何を決めたか

共著作品の許諾料を、契約の形に合わせて 2 通りで持つ。

| 契約の形 | 例（電子書籍印税の実データ） | 持ち方 |
|---|---|---|
| **代表受取**：代表 1 者が当社から全体（10%）を受け取り、自分で分配する | 力造┴N.G.P. → ダックルーズに 100%。鈴吹┴F.E.A.R. → F.E.A.R. に 100% | 従来どおり条件明細 1 本（相手先＝代表）。分配は当社から見えないので持たない |
| **直接分配**：当社が各権利者に直接払う（A 6% / B 4%） | 光砕のリヴァルチャー → 瀧里 75% / 宝井 25%。カローン → 番棚 30% / 佐々宮 40% / 初夏 30% | 条件明細 1 本（全体率 10%）＋**取り分明細**（A 60% / B 40%） |

- **条件明細は作品 × 媒体で 1 本**。全体率（`conditions.rate_ppm`）と契約の当事者（`counterparty_id`）を持つ。
- **取り分明細 `v3.condition_shares`** は、当社から直接払う相手が 2 者以上のときだけ付く。条件 × 権利者 × 取り分（百万分率）。合計 100%。
- 分配率も支払先も**作品ごと**に決まる。同じ著者の組でも作品で違う（番棚／佐々宮は 50/50 と 30/40/30）。著者名の文字列（「┴」区切りのクレジット）からは導かない。
- **買い切り**（当社が権利を保有）は、定額（`pricing_model='fixed'`）の IN 条件 1 本で持つ。料率条件が無いので印税計算の対象から外れる。取り分とは無関係。
- 作品マスタに「印税対象外」の旗は持たない。売上データの作品に料率条件が無ければ印税なし、条件が 1 本も無ければ登録漏れ、として取込時に見分ける（取込は未実装。§6）。

## 2. 端数

事業部と合意した決まり（`royalty/shares.ts` の `allocateShares`）。

1. 全体額は条件 1 本で出す（料率は四捨五入。`royalty/rounding.ts`）。
2. 受取人ごとに 全体額 × 取り分 を**四捨五入**する。
3. 四捨五入の合計が全体額を**超えたら**、繰り上げ幅が大きい行から順に 1 円ずつ引く。同点なら後ろの行から。
4. 合計が全体額を下回るぶんはそのまま（全体率を超えないことだけを守る）。

例：9,045 円を 50/50 → 4,522.5 と 4,522.5 → 四捨五入 4,523 × 2 = 9,046 は超過 → 後ろを 4,522 にして 4,523 + 4,522 = 9,045。

Excel（従来の手計算）は明細行ごとに切り捨て、分配は端数を残していた（4,522.5 円）。1 円単位で差が出る。

消費税は受取人の額に掛けて切り捨て。源泉は**受取人**で決まる（個人なら源泉、法人なら無し。非居住者は A-057 のとおり）。条件の相手先ではない。

## 3. 計算書

1 枚の紙は 1 人宛て。取り分のある条件の計算書は**受取人ごとに 1 枚**。

- `statements.payee_party_id` / `share_ppm` … その計算書が誰の・何 % の分か。空なら従来どおり（相手先 1 者に 100%）。
- 同じ文書に同じ条件の計算書は受取人ごとに 1 本（一意索引 `statements_document_condition_payee_uq`。A-020 の索引を差し替え）。
- 実績（`condition_events.document_id`）を指すのは最初に出した受取人の文書だけ。ほかの受取人の文書は明細（`statement_lines.event_id`）で同じ実績に繋がる。試算・確定は、ほかの受取人の計算書に結ばれた実績を「空いている」として扱い、同じ受取人にはもう出さない（`statement-service.ts` の `resolveInput`）。
- 支払（`payments/service.ts` の `createFromStatementDocument`）は受取人へ立てる。二重払いの検査は、その受取人への支払だけで見る（同じ実績に受取人の数だけ支払が立つのは正しい）。
- 紙の宛名・口座・源泉の欄は受取人（`manual_inputs._payeePartyId` → `documents/context-repository.ts`）。

### 3.1 流れ

1. 条件明細の画面 › 「取り分（共著）」で、受取人と % を入れる（`PUT /conditions/:id/shares`。取得の料率の許諾条件だけ。MG・AG のある条件には付けない：受取人ごとの計算書で前払保証の消化を分けて数える道がまだ無いため）。
2. 台帳（作品 › 利用許諾計算）は従来どおり条件の相手先（代表）の下に回が立つ。条件の欄に「取り分：A 60%・B 40%」と出る。
3. 回の「計算書を作る」→ 文書の画面。試算（`/statement-documents/preview`）は受取人を選ぶ前は**全体**の額で、取り分ごとの内訳（`shares`）を添える。「受取人（共著の取り分）」で 1 人選ぶと、その人の額で試算し直す。
4. 決定（`/statement-documents`）は受取人が必須。受取人の違う条件は 1 枚にまとめられない。
5. ほかの受取人は、同じ実績を選んでもう 1 枚出す。

条件の画面から直接出す道（`/conditions/:id/statement-documents`。OUT 条件向け）も `payeePartyId` を受ける。

## 4. 表・列

```

                     share_ppm 1..1000000, sort_order, note)   UNIQUE (condition_id, party_id)
v3.statements.payee_party_id → parties   （空＝条件の相手先）
v3.statements.share_ppm                  （空＝100%）

```

## 5. 事業部の電子書籍データとの対応

事業部から来る 2 つの Excel：

- 月次「電子書籍売上報告」… 販売月・書店・タイトル・著者名（┴区切り）・CID・販売価格・料率（書店の掛率）・DL数・税抜き金額。印税は `ROUNDDOWN(販売価格 × DL数 × 15%)`。
- 年次「電子書籍印税計算」… 支払先ごとのシートと「印税内訳」（支払先コード 2-20-xxxx／企業・本名・税抜・税込）。分配はシート末尾の数式（`=L50*0.75` など）。

対応：

| Excel | V3 |
|---|---|
| タイトル名称／CID | `works`（CID は作品の外部コードとして持つ。2025年10月分から付いている） |
| 著者名（┴区切り） | 表示用クレジット。`work_credits` / `works.copyright_notice`。支払先には使わない |
| 支払先シート・印税内訳 | 条件明細の相手先（代表受取）または取り分明細（直接分配） |
| 15% | 条件明細の全体率 |
| `=L50*0.75` | `condition_shares.share_ppm = 750000` |
| 印税支払除外品（Role&Roll 本誌・買い切り） | 料率条件の無い作品（買い切りは定額条件）。取込で印税なしとして静かに飛ばす |
| アークライト売上 ×0.99 | **保留**。印税ではなく別精算の可能性。登録の仕方は確認待ち |

作品ごとの現状（Excel から逆算した支払先と分配率の一覧）は、契約書と突合してからマスタに入れる。

## 6. まだ無いもの

- **電子書籍売上の取込**。月次 Excel を読んで作品（CID）に当て、`condition_events`（`usage_type='pub_digital'`、販売価格 × DL数 の報告売上）を作る道。既存の CSV 取込（`imports/service.ts`）はマスタ用で、売上は入らない。
- 台帳を受取人ごとに引く（いまは条件の相手先の下にだけ回が立つ）。
- 出版条件書の「共同著作・第三者権利」欄を取り分明細から組む（いまは `third_party_rights` の自由テキスト）。
- 取り分のある条件に MG・AG を付ける（受取人ごとの消化の数え方を決めてから）。
