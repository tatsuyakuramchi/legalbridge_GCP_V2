# 許諾料の台帳（作品 › 利用許諾計算）

対象: `apps/legalbridge-v3`（A-059）

## 1. 何をするか

作家から取った権利（許諾・IN の条件）に対して払う利用許諾料を、**作家 × 作品**（切り替えて **作家 × 全作品**）の台帳で回していく。条件は1回作れば、毎期その料率・MG・AG を使い回し、回ごとに実績を揃えて計算書を出す。

- 置き場所は **作品のページの「利用許諾計算」タブ**。その作品を許諾している作家ごとに台帳がある。
- 受付箱で「案件にせず処理」した計算書の依頼（docs/v3-request-inbox.md §8）は、**人が選んで**台帳の回に紐づける（自動では付けない）。依頼 → 作家・作品・回、作家・作品の回 → 依頼 の両方向から紐づけ・行き来できる（§5）。紐づけた回で出した計算書で、依頼の工程（作成→送付→支払予定→支払）が進む。

データはほとんど増やさない。条件・予定明細（締め）・実績・計算書・支払から「回」を組み立てて見せる（`server/royalty/ledger-service.ts`）。計算（料率・MG・AG・消費税・源泉）は既存の束ねた計算書（`/statement-documents`）がする。

## 2. 回（round）

計算書1枚の単位。2種類ある。

| | 時限式（periodic） | イベント式（event） |
|---|---|---|
| 回ができるきっかけ | 予定明細（`condition_schedules`・`periodic`）の締め日 | 製造・刷の実績1件 |
| 実績の入り方 | 実績が回（`schedule_id`）を指していればその回。指していなければ発生日が「前の締めの翌日〜その回の締め」に入る回 | その実績だけ |
| 支払日 | 予定明細の支払日（`pay_on`） | 製造日から条件の支払条件（製造月の翌月末など）で出す |
| まとめ方 | 同じ支払日の回を1枚にする（下） | まとめない（その回だけで1枚） |

- 出し方は条件ごとに持つ（`conditions.statement_timing`）。空なら利用形態から決める：**紙出版はイベント式、それ以外は時限式**。台帳の条件の欄で切り替えられる。
- どの回にも入らない実績（予定明細が無い・範囲の外）は「予定の外」の回として別に出す（黙って落とさない）。締めの無い時限式の条件には「締めなし」と出し、その場で締めを作れる（あれば「締めを足す」で後ろに足す）。
- 締めを作る画面（`client/RoyaltyCloses.tsx`）で立てるのは**時期だけ**：周期（四半期・半年・年1回・毎月）・最初の締め日・回数・支払日の決め方（条件の支払条件どおり／締め月の翌月末・翌々月末・3か月後の月末）。対象期間の名前（2026年7〜9月）は締めから付く。数量・金額は報告が来てから実績で入れるので、ここでは聞かない（予定明細には 0 円で入る。料率・許諾の単価の条件は 0 円の回を置ける）。汎用の予定明細の画面（金額・契約形式・役務提供期間）は使わない。締めがある条件では同じ画面が「締めを直す・足す」になり、いまの締めの対象期間・締め日・支払日を直せる（締め日を直せばその回の期間の終わりも合う）。実績の無い回は「外す」で消せる。実績の付いた回は外せない（日付は直せる）。

### 2.1 契約ごとに締めがずれる

締め月・締め日・支払日の決め方・起点（暦の四半期か契約日起算か）は条件の予定明細が持つ。回をまとめる単位は**期ではなく支払日**なので、3・6・9・12月締めの契約と 2・5・8・11月締め（翌々月末払い）の契約でも、支払日が同じなら1つの回になる。計算書の行には条件ごとの対象期間がそのまま出る。

### 2.2 作家の計算書のまとめ方

`parties.royalty_bundle`：

- `per_work`（既定・空）… 作品ごと。同じ作品の中は支払日でまとめる。
- `per_party` … 作家でまとめる。「この作家の全作品」で見たとき、同じ支払日の回を作品をまたいで1枚にする。

まとめると1回の支払が 100万円を超えやすく、超えた部分の源泉は 20.42% になる（`royalty/tax.ts`）。試算で確かめてから出す。

## 3. 回の中（part）

条件 × その回。状態は 締め前 / 報告待ち / 入力済 / 報告なし / 計算書済。

- **報告なし**（`royalty_round_skips`）… 報告が来なかった回。**人が切り替える**（自動では付けない）。実績が入っている回には付けられない。取り消せる。
- 実績の無いまま締めが過ぎた回は、報告なしにするまで「報告待ち」のまま開いている回に残る。V3 より前から続く条件の古い予定明細は、「空の回をまとめて報告なしに…」で日付を決めて一度に閉じる（その日より前の締めで、実績の無い回だけ。実績のある回・締め前の回には触らない）。
- **来るはずの行** … 前の回にあった行（利用形態・許諾先・作品）と、生きている許諾先（OUT 条件。再許諾・他社販売）のうち、今回まだ無いもの。数字を入れれば実績になる（「実績を入れる」は条件の実績のフォームを、その回を選んだ状態で開く）。

### 3.1 実績の言語・地域（A-061）

1本の許諾（OUT 条件）で英語・フランス語を出していても、相手からの報告は英語版・フランス語版で別々に来る。条件は利用形態ごとに1本のまま、**言語・地域は実績が持つ**（`condition_events.scope_languages`・`scope_regions`。空は指定なし）。

- 実績の入力：選んだ許諾先の許諾言語（地域）が2つ以上なら、「この報告の言語」を選ぶ（言語は必須、地域は任意）。許諾先の範囲の外（英語・フランス語の許諾にドイツ語）は止める。全言語・全世界の許諾なら見ない。
- 台帳の行：利用形態・許諾先・作品に加えて言語・地域で見分ける。許諾先の許諾言語・許諾地域で **言語×地域ごとに1行**の「来るはず」を出す（英語×北米は来た・英語×欧州とフランス語×欧州はまだ、が分かる。1つしか無くても行に持つので、報告に言語・地域が入る。「全言語」「全世界」は分けない）。言語・地域を持たない古い報告・行はその組を覆うとみなし、前の回から来た行が言語・地域を欠いていれば許諾先の範囲で埋める。1つの締めには許諾先×言語×地域ごとの報告が何件も付く（許諾の条件の締めは `claimSchedule` の二重付けの検査を通さない）。その行の「数字を入れる」で、許諾先・言語・地域・回・発生日（締め日）が入った状態で数字だけ打つ。
- 計算書：行の製品名の後ろに言語・地域を添え（「ito｜英語・フランス語｜欧州｜Alpha Games（フランス語）」）、許諾範囲の欄は許諾先の範囲全体ではなくその報告の言語・地域を出す。

### 3.2 回の画面（`client/RoyaltyLedger.tsx`・`RoundReport.tsx`）

画面は台帳と文書の2枚だけ。左に回の一覧（開いている回・終わった回）、右に選んだ回の中身を、上から下へ進む3段で出す。

1. **報告を入れる** … 行（許諾先・製品 × 言語 × 地域）の表。来るはずの行が先に並び、相手から来た数字（数量・単価・受領額）をその行に打って「記録」。利用形態・許諾先・言語・地域・回は行が持っているので聞かない。発生日は締め日で入る。汎用の実績フォーム（条件明細の ConditionEvents）は台帳では開かない。予定にない報告は「＋ 予定にない報告を足す」で条件 → 許諾先 → 言語 → 地域 を選んで足す。
2. **計算書を作る** … 入力済の報告で試算を出し、「計算書を作る（文書の画面へ）」でその回の条件・実績・ひな形を選んだ状態で文書の画面を開く。報告待ちの行があれば注意を出す（待たずに出せば入力済の分だけの計算書）。
3. **送付・支払** … 決定した計算書（番号は文書のページへ）、支払、受付箱の依頼の紐づけ。

文書の画面の上には「← 作家 × 作品 の台帳へ戻る」が出る（台帳から計算書を作りに来たとき・台帳から決定した文書を開いたとき）。条件の出し方・締め・計算書のまとめ方は「条件と締めの設定…」を押したときだけ開く。

### 3.3 予定の行（A-062）

数字はまだ無いが、この許諾先・言語・地域から報告が来るはず、という行を人が先に置く（`royalty_expected_lines`）。回の「＋ 予定を作る」で 作品・利用形態 → 許諾先 → 言語 → 地域 → いつから（この回から／次の回から）を選ぶ。`from_on` 以降の締めの回で「来るはず」として待ち（前の回にあった行と同じ扱い）、数字が来たら「数字を入れる」で実績になり、その回からは予定の行は消える。来なければ「報告なし」（回ごと）か「予定を外す」（行を消す。実績は消えない）。「＋ 報告を追加」で記録した行も、以後の回では自動的に来るはずになる。

### 3.5 決定した計算書に載った報告の例外修正（admin）

相手の報告が間違っていた・打ち間違えた、が計算書を決定したあとに分かったとき。台帳の「計算書済」の行の「修正して出し直す」（admin だけ）で、数量・単価・受領額・発生日を直し、理由を書いて「直して訂正版を出す」。

1. `POST /royalty-ledger/corrections` … 実績を直す（A-041 の `events.amend` を通す。理由と前後の値が監査に残る）。数量・単価・受領額・発生日に加えて**言語・地域**も直せる（許諾先の許諾範囲の外は弾く）。直した言語・地域は、計算書の製品名の「（フランス語）」と許諾範囲の欄にそのまま出る。利用形態のある実績は許諾料（実額）を条件の料率で計算し直す。支払が立っていれば直せない（先に支払を取り消す）。
2. そのまま文書の画面が開く（`start.supersedesId`・`reason`）。元の計算書に結ばれた実績（直したものを含む）と条件を選んだ状態で、訂正版として試算し直す。`/statement-documents/preview`・`/statement-documents` は `supersedesId` を受け取り、その文書に結ばれた実績を「空いている」ものとして扱う。
3. 決定すると、元の計算書は「訂正版あり」（superseded）に退き、実績は新しい版に移る（`issue-service.supersede`）。決定するまで元の版は有効なまま。

### 3.6 支払と OUT 条件から見た報告

- 計算書を決定しても支払は自動では立たない（経理提出用の帳票は支払から作る）。決定済みで支払の無い計算書は、台帳の行と「3 送付・支払」に **支払なし** と出し、その場の「支払を立てる」（`POST /documents/:id/payment`）で立てる。条件明細の実績一覧も同じ（実績ごとに割り当てた支払の番号か「支払なし」）。
- 台帳で入れた締め・実績は、許諾料を払う側の **IN 条件（作家）** に付く。許諾先の **OUT 条件** の画面には付かないので、OUT 条件の詳細に「この許諾先からの報告」（`GET /conditions/:id/out-reports`：その許諾先を指す実績と、対応する IN 条件・締め・計算書へのリンク）を出す。

### 3.7 一律の IN 条件と許諾先専用の IN 条件（A-063）

取得（IN）の再許諾・他社販売の条件は、ふつう **作家 × 作品 で 1 本（一律）**。その作品の許諾先（OUT 条件）すべてに効き、台帳はその下に 許諾先×言語×地域 の行を並べる。相手先は作家、許諾先は OUT 条件の相手先。IN 条件の相手先を許諾先にしない。

契約が特定の許諾先だけ別の料率にしているときだけ、IN 条件に **対象の許諾先**（`conditions.target_party_id`）を持たせる（**許諾先専用**）。台帳はその許諾先の OUT 条件の行だけをこの条件の下に並べ、同じ作品・利用形態の一律の条件からはその許諾先を外す。条件名は「作品名｜再許諾（許諾先／目的）」になる。

フォーム（条件を登録・出版セット・条件の編集）の「対象の許諾先」は任意で、空＝一律。条件明細の見出しと台帳の条件の欄に「一律（全許諾先）」「許諾先専用：◯◯」と出る。

### 3.4 入口

- 作家カードに「▶ 次：1〜3月の回に報告待ちが 2 行」を出す（`WorkRoyaltyParty.next`）。押すとその回を開く。報告待ちが無ければ「締め前」「締めがありません」。
- 回の上の手順の帯（1 作家 → 2 回 → 3 報告を入れる → 4 計算書）で、いまどこにいるかと次の一手（「最初の報告待ちへ ↓」「＋ 報告を追加」）を出す。
- 作家 × 全作品では、報告の表を作品名の帯で区切る。帯にはその作品の条件と「＋ この作品の報告を追加」。この回に締めの無い作品は帯だけ出す。

## 4. 回の状態

| 状態 | 条件 |
|---|---|
| 締め前 | どの行もまだ締めが来ていない |
| 実績を入力中 | 報告待ちの行がある |
| 計算書を作れる | 全部の行が入力済・今期は無し・計算書済 |
| 計算書を決定 | 全部の実績が決定した計算書に結ばれた |
| 送付済 | その計算書をメールか CloudSign で送った |
| 支払予定 | その実績に割り当てた支払がある |
| 支払済 | その支払がすべて支払済み |
| 支払なし | 計算書の差引額が 0（AG 充当だけなど） |

支払済・支払なし・報告なしは「これまでの回」（年ごと）に移る。それ以外は「開いている回」。

## 5. 依頼と回の紐づけ（A-060）

計算書の依頼が台帳のどの回の分かは、人が選ぶ。回は、回を作っているもので指す（`intake_request_links`）。

- `schedule` … 時限式の回（予定明細の行。条件ごとに1行あるので、回のすべての行を繋ぐ）
- `event` … イベント式の回（製造・刷の実績）・予定の外の回（実績）

繋ぐと、その回の条件も依頼に繋ぐ（`condition`）。

| 向き | 画面 |
|---|---|
| 依頼 → 作家・作品・回 | 受付箱の依頼の「作家・作品と回」。依頼に繋いだ条件の作家・作品（無ければ作家を名前で探す）→ 回を選んで紐づける。台帳で開く・回を外すもここ |
| 作家・作品の回 → 依頼 | 台帳の回の「受付箱の依頼」。案件にせず処理中の依頼から選んで紐づける（★ はこの作家・作品の依頼）。依頼番号を押すと受付箱のその依頼を開く |

- 作家・作品には繋がっているが、まだ回を選んでいない依頼は、台帳の「開いている回」の上に「回を選んでいない依頼」として出る。
- 依頼の工程は、紐づけた回の実績を載せた計算書から導く（`intake/payment-request.ts`）。

## 6. 経路

| メソッド | パス | 権限 |
|---|---|---|
| GET | `/api/v3/works/:id/royalty` | 閲覧（作品を許諾している作家の一覧） |
| GET | `/api/v3/royalty-ledger?partyId=&workId=` | 閲覧（workId を外すと作家 × 全作品） |
| POST / DELETE | `/api/v3/royalty-ledger/skips`（`conditionId`・`scheduleId`） | admin / legal |
| POST | `/api/v3/royalty-ledger/corrections`（`conditionId`・`eventId`・`reason`・数量/単価/受領額/発生日） | admin |
| POST / DELETE | `/api/v3/royalty-ledger/plans`・`/plans/:id`（`conditionId`・`outConditionId`・`languages`・`regions`・`fromOn`） | admin / legal |
| POST | `/api/v3/royalty-ledger/skips/before`（`partyId`・`workId`・`before`） | admin / legal |
| POST | `/api/v3/intake/:id/rounds` ・ `/rounds/unlink`（`scheduleIds`・`eventIds`） | admin / legal |
| PUT | `/api/v3/royalty-ledger/timing`（`conditionId`・`timing`） | admin / legal |
| PUT | `/api/v3/royalty-ledger/bundle`（`partyId`・`bundle`） | admin / legal |

計算書の試算は既存の `/statement-documents/preview`（その回の、まだ文書に結ばれていない実績）。台帳からは計算書を直接決定しない。決定すると作成のフォームは閉じ、決定した文書のページを開く（決定した文書は直せない。直すなら訂正版）。台帳の「計算書済」の横の番号と、実績の一覧の文書番号からも決定した文書のページへ行ける。「この回の計算書を作る」は文書の画面を、その回の条件・実績・ひな形を選んだ状態で開き、そこで中身と手入力の項目（行の見出しなど）を確かめて、下書き保存・決定する。

## 7. データ（`infra/v3/004_amend.sql` A-059）

- `conditions.statement_timing`（periodic / event / 空）。改訂でも引き継ぐ。
- `parties.royalty_bundle`（per_work / per_party / 空）。
- `royalty_round_skips(condition_id, schedule_id, reason, created_by, created_at)`。
- A-060：`intake_request_links.target_type` に `schedule`・`event` を足す。
- A-061：`condition_events.scope_languages`・`scope_regions`（text[]）。
- A-062：`royalty_expected_lines(id, condition_id, out_condition_id, scope_languages, scope_regions, from_on, note, created_by, created_at)`。
