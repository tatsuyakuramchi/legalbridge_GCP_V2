# 許諾料の台帳（作品 › 利用許諾計算）

対象: `apps/legalbridge-v3`（A-059）

## 1. 何をするか

作家から取った権利（許諾・IN の条件）に対して払う利用許諾料を、**作家 × 作品**（切り替えて **作家 × 全作品**）の台帳で回していく。条件は1回作れば、毎期その料率・MG・AG を使い回し、回ごとに実績を揃えて計算書を出す。

- 置き場所は **作品のページの「利用許諾計算」タブ**。その作品を許諾している作家ごとに台帳がある。
- 受付箱で「案件にせず処理」した計算書の依頼（docs/v3-request-inbox.md §8）は、台帳の回に付けて見せる。依頼の画面の「◯◯ の利用許諾計算で開く」から、その作品・作家の台帳へ直接移れる。台帳で出した計算書で、依頼の工程（作成→送付→支払予定→支払）が進む。

データはほとんど増やさない。条件・予定明細（締め）・実績・計算書・支払から「回」を組み立てて見せる（`server/royalty/ledger-service.ts`）。計算（料率・MG・AG・消費税・源泉）は既存の束ねた計算書（`/statement-documents`）がする。

## 2. 回（round）

計算書1枚の単位。2種類ある。

| | 時限式（periodic） | イベント式（event） |
|---|---|---|
| 回ができるきっかけ | 予定明細（`condition_schedules`・`periodic`）の締め日 | 製造・刷の実績1件 |
| 実績の入り方 | 実績が回（`schedule_id`）を指していればその回。指していなければ発生日が「前の締めの翌日〜その回の締め」に入る回 | その実績だけ |
| 支払日 | 予定明細の支払日（`pay_on`） | 製造日から条件の支払条件（製造月の翌月末など）で出す |
| まとめ方 | 同じ支払日の回を1枚にする（下） | まとめない（その回だけで1枚） |

- 出し方は条件ごとに持つ（`conditions.statement_timing`）。空なら利用形態から決める：**紙出版はイベント式、それ以外は時限式**。台帳の条件の欄で切り替えられる。
- どの回にも入らない実績（予定明細が無い・範囲の外）は「予定の外」の回として別に出す（黙って落とさない）。予定明細の無い時限式の条件には「予定明細なし」と出し、その場で締めを作れる。

### 2.1 契約ごとに締めがずれる

締め月・締め日・支払日の決め方・起点（暦の四半期か契約日起算か）は条件の予定明細が持つ。回をまとめる単位は**期ではなく支払日**なので、3・6・9・12月締めの契約と 2・5・8・11月締め（翌々月末払い）の契約でも、支払日が同じなら1つの回になる。計算書の行には条件ごとの対象期間がそのまま出る。

### 2.2 作家の計算書のまとめ方

`parties.royalty_bundle`：

- `per_work`（既定・空）… 作品ごと。同じ作品の中は支払日でまとめる。
- `per_party` … 作家でまとめる。「この作家の全作品」で見たとき、同じ支払日の回を作品をまたいで1枚にする。

まとめると1回の支払が 100万円を超えやすく、超えた部分の源泉は 20.42% になる（`royalty/tax.ts`）。試算で確かめてから出す。

## 3. 回の中（part）

条件 × その回。状態は 締め前 / 報告待ち / 入力済 / 今期は無し / 計算書済。

- **今期は無し**（`royalty_round_skips`）… 報告が来なかった回。人が付け外しする。実績が入っている回には付けられない。
- **あとの回に実績がある空の回**は「報告なし」と読む（人が付けた「今期は無し」とは別。V3 より前から続く条件の古い予定明細が、報告待ちとして並び続けないように）。台帳の「これまでの回」にも出さない。
- **来るはずの行** … 前の回にあった行（利用形態・許諾先・作品）と、生きている許諾先（OUT 条件。再許諾・他社販売）のうち、今回まだ無いもの。数字を入れれば実績になる（「実績を入れる」は条件の実績のフォームを、その回を選んだ状態で開く）。

## 4. 回の状態

| 状態 | 条件 |
|---|---|
| 締め前 | どの行もまだ締めが来ていない |
| 実績を入力中 | 報告待ちの行がある |
| 計算書を作れる | 全部の行が入力済・今期は無し・計算書済 |
| 計算書を決定 | 全部の実績が決定した計算書に結ばれた |
| 送付済 | その計算書をメールか CloudSign で送った |
| 支払予定 | その実績に割り当てた支払がある |
| 支払済 | その支払がすべて支払済み |
| 支払なし | 計算書の差引額が 0（AG 充当だけなど） |

支払済・支払なし・報告なしは「これまでの回」（年ごと）に移る。それ以外は「開いている回」。

## 5. 経路

| メソッド | パス | 権限 |
|---|---|---|
| GET | `/api/v3/works/:id/royalty` | 閲覧（作品を許諾している作家の一覧） |
| GET | `/api/v3/royalty-ledger?partyId=&workId=` | 閲覧（workId を外すと作家 × 全作品） |
| POST / DELETE | `/api/v3/royalty-ledger/skips`（`conditionId`・`scheduleId`） | admin / legal |
| PUT | `/api/v3/royalty-ledger/timing`（`conditionId`・`timing`） | admin / legal |
| PUT | `/api/v3/royalty-ledger/bundle`（`partyId`・`bundle`） | admin / legal |

計算書の試算と作成は既存の `/statement-documents/preview`・`/statement-documents`（その回の、まだ文書に結ばれていない実績）。

## 6. データ（`infra/v3/004_amend.sql` A-059）

- `conditions.statement_timing`（periodic / event / 空）。改訂でも引き継ぐ。
- `parties.royalty_bundle`（per_work / per_party / 空）。
- `royalty_round_skips(condition_id, schedule_id, reason, created_by, created_at)`。
