# 発注書から検収書・役務提供完了通知書を作る

画面：支払文書 →「発注書から検収書」、または決定済みの発注書の詳細画面の「この発注書から検収書を作る」。サーバ：`apps/legalbridge-v3/src/server/documents/from-order.ts`。

## なぜ

業務委託の 1 つの業務は 委託料＋実費（交通費など）＋手数料 の条件が組で動くが、実費・手数料は独立した条件。
委託料の条件から検収書を作ると実費の条件が選ばれず、交通費が紙にも支払にも載らなかった。
発注書を決定すると、発注書の経費・その他手数料の行も条件になって発注書に結ばれる（`settlement-conditions.ts`）。
**決済文書に載せる条件を、元の発注書に結んだ条件だけにする**と組が揃う。

## 流れ

1. 発注書を選ぶ（決定済みの `purchase_order` / `intl_purchase_order`。番号・件名・相手先で探す）
2. 載せる実績（委託料の納品・役務の記録）を選ぶ。検収済みの実績は選べない
3. 実費・手数料ごとに
   - **かかった**：実額（経費は税込）・利用日・備考。発注書の見込みの額は初期値で、そのまま刷らない
   - **今回はかからなかった**：今回の文書に載せない（次の回で使える）
   - **かからなかった（以後も発生しない）**：載せず、決定のとき条件を完了扱いにする
   - 発注書に無かった実費・手数料も足せる（決定のとき条件になる）
4. 下書きを作る → 文書の画面で確かめて決定

ひな形は、海外の発注書なら海外の検収書、準委任・時間精算なら役務提供完了通知書、ほかは検収書（画面で変えられる）。

## 決定のとき

- かかった実費の行に実績を立てて文書に結ぶ（`settleExtraRows`）。同じ額の未決済の実績が先にあれば、立て直さずそれを結ぶ
- 「以後も発生しない」とした実費・手数料（`_closeExtrasOnIssue`）を完了扱いにする

## API

- `GET /api/v3/orders/search?q=` 決定済みの発注書の候補
- `GET /api/v3/orders/:id/settlement-plan` 発注書の委託料（実績つき）と実費・手数料
- `POST /api/v3/orders/:id/settlement-draft` `{ templateKey?, eventIds, extras: [{ conditionId|null, kind, name, status, amount?, spentOn?, remarks? }] }` → 下書きの id
