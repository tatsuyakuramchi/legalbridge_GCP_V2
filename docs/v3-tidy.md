# 整理する ― 取引先の木を 1 本ずつ直す

本線（登録 → 作る → 確かめる → 送る → 記録）の外で、台帳を健全にする工程。
画面は 横断で見る › 取引先⇔基本契約 › 整理する（見出しの切り替え）。API は `GET /tidy/parties` と `GET /tidy/parties/:id`。
組み立ては `server/ops/tidy.ts`（純粋）、行集めは `server/ops/tidy-service.ts`、画面は `client/TidyWorkspace.tsx`。

## 木

```
取引先
 └ 取引（基本契約 or 独立契約）
    └ 個別契約（条件書・発注書）
       └ 条件（作品）
          ├ 実績
          ├ 支払文書（計算書）
          └ 支払
```

契約の層は 取引先⇔基本契約のマップ（`agreements/party-map.ts`）をそのまま使う。条件から下はここで引く。

## 取引の 3 つの型

| 型 | 形 | 一意キー | 多重 |
|---|---|---|---|
| 1 | 基本契約 ＋ 個別契約 ＝ 1 取引（`kind=master` と、その下の `supplement`・発注書） | 取引先 × 基本契約 | 同じ取引先に期間の重なる有効な基本契約が 2 本 |
| 2 | 独立契約 ＝ 1 取引（`kind=standalone`。基本契約の無い発注書も 1 取引） | 取引先 × 独立契約 | 同じ取引先・同じ作品・同じ用途で期間の重なる独立契約が 2 本 |
| 3 | 複数当事者 ＝ 1 文書・N の関係 | 型 1・2 と同じ（根の契約） | 文書 ID・条件 ID で重複を除いてから数える |

型 3 の表し方（A-075。`infra/v3/172_multi_party.sql`、`server/parties/multi-party.ts`）：
- 共著は条件の相手方（代表）＋ `condition_shares`（取り分）。受取人の木には「受取人として（共著の取り分）」の枝に同じ条件を出し、自分宛ての計算書・支払だけを見せる。多重には数えない。
- 連名の文書（連名の条件書・3 社契約）は `document_parties`（文書 × 取引先 × 役割：相手方／共著者／譲渡人／譲受人／承諾者／署名者）。文書は 1 件のまま、宛名は変えない。
  文書の画面「関係当事者」で足す。載せた取引先の木には「関係当事者として（連名の文書）」の枝に同じ 1 件が出る。文書の一覧・検索の取引先の絞り込みにも当たり、CloudSign の署名者の候補にも入る。
  API：`GET/PUT /documents/:id/parties`。
- 地位承継（3 社契約）は `agreement_successions`（契約・誰から誰へ・発効日・根拠の文書）。契約の画面「地位承継」で登録する。
  発効日が今日以前ならその場で、先なら日次（`jobs/daily.ts`）で、契約・その下の個別契約・それらに載る条件の相手方を 旧 → 新 に切り替える。発効日前の実績・支払文書・支払は旧宛てのまま。戻せる。
  木では、取引の説明に「承継予定 → ◯◯（発効日から）」「◯◯ から承継」と出し、譲渡人の木には「承継で移った取引」の枝に足跡を残す。
  API：`GET/POST /agreements/:id/successions`、`POST /successions/:id/apply|revert`、`DELETE /successions/:id`。

## 4 つの印と直し方

| 印 | 意味 | 直し方 | 叩く API |
|---|---|---|---|
| 多重 | 同じものが 2 つ | 統合する | 取引先：`POST /parties/merge`。計算書：`POST /royalty-ledger/statements/merge`。基本契約・条件の重複は開いて片方を解除・差し替え |
| 未登録 | 外にあるが台帳に無い | 登録する | `POST /agreement-map/documents/:id/agreement`（番号を変えずに契約を立てる） |
| 欠け | 親子が繋がっていない | 繋ぐ | 条件→契約：`POST /links/condition/:id/agreement`。個別契約→基本契約：`PATCH /agreement-map/agreements/:id {parentId}`。実績の取り残し・支払の無い計算書は開いて直す |
| 空 | 欄が空 | 埋める | 許諾期間：`POST /conditions/term-default`。通知先：`POST /notice-fill`。種別：`PATCH /agreement-map/agreements/:id {domain}` |

この画面だけの書き込みは無い。印の `fix` に今ある道具への指示を載せ、画面はその API を叩く。

判定の決まり：
- 条件の多重：同じ作品・同じ種類・同じ用途・同じ向き・同じ値段（率・額）で、期間の重なる有効な条件が 2 本以上。自動更新は終わりが無い扱い。
- 実績の欠け：支払に割り当て済みの実績より前の日付なのに、割り当たっていない実績がある（取り残し）。
- 計算書の欠け：決定済みなのに支払が無い。
- 差し替え済み・取消の条件、差し替え済みの文書は木に出さない（運用 › 片づけ の対象）。

## 画面

左に取引先（直すところのある順）、中に木、右に押した印の直し方。「直すところだけ」で印の無い枝を落とす。
直した結果が紙に出るものは訂正版で出し直す（運用 › 一括修正 と同じ道具）。
